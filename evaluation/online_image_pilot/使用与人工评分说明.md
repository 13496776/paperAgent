# 在线图像研究文献检索试测集

本目录包含 `online_image_dialogues.json`，共 8 个中文任务，覆盖图像编辑、图像修复、图像生成、图像超分辨率、二次检索和跨方向比较。最后两例为多轮对话；每例使用独立会话，按 `user_turns` 顺序输入并确认执行计划。任务仅要求在线搜索，不要求下载、导入论文或更改语料库。

## 时间及 CCF 核验

- 为便于复测，“近三年”固定为 **2023-11-24 至 2026-11-24（含首尾日期）**，以会议论文正式发表日期为准。arXiv 的 `published` 是预印本首次公开时间，不等于会议正式发表时间；会议年份单独出现且无法确认日期时标为待核验，不可直接判定满足窗口。未来如果要滚动更新范围，应新建版本并在报告中写明，避免与原结果直接比较。
- 应预先选定并记录所采用的 CCF 推荐目录版本。会议/论文集归属以会议官网、官方论文集或出版社来源为依据；CCF 等级以相应版本官方目录核验。会议简称相似时应核对完整名称和届次。未能核验的条目可保留为“待核验候选”，不可算作已确认 CCF-A 成果。
- 当前在线工具 `search_arxiv` 查询的是 arXiv API，主要提供预印本题录、摘要、链接和部分 DOI，并不保证包含正式发表信息，也不会自动核实 CCF 等级。Agent 如果仅有这些信息，正确行为是报告限制、提供候选并提示人工核验；不要因为未能验证就伪造会议或 DOI。
- 在线结果会随访问时间、网络、索引和预印本版本变化。本集没有固定论文或完整相关论文金标，不适合直接计算完整检索召回率。

## Linux 运行

正常模式下启动系统，即可提供在线工具：

```bash
unset PAPER_EVALUATION_LOCAL_ONLY
python run_paperagent.py
```

登录前端后，打开 `online_image_dialogues.json`，把每例的第一条 `user_turns` 输入研究栏；有后续轮次的案例要在同一会话中按顺序输入。每例换一个会话。按你的要求，人工检查最终结果和工具调用记录即可。本集不能直接使用 `evaluation/run_pilot.py`，该脚本是为本地隔离测试写的，会要求禁用在线工具并检查固定的本地语料。

## 建议记录和计算

每例根据 JSON 中 `manual_checks` 和结果记录 `manual_result`。建议另存副本，不修改仓库原始测试集。字段含义：

- `completion`：任务是否满足全部适用要求；诚实说明无法核验是合格边界行为，不能把不可靠条目算成已确认论文。
- `tool_selection_correct`：是否在需要时调用 `search_arxiv`，且未发生用户未要求的论文导入；多轮二次检索案例还需检查第二轮调用。
- `tool_calls_succeeded`：记录成功次数与实际执行次数，例如 `{"success": 2, "attempts": 3}`；仅有失败回执、超时、429 不算成功。模型说明不可用与工具执行成功是不同概念。
- `relevant_candidates`：记录在线搜索结果中经人工确认与主题相关的候选数，以及人工核查的候选总数。注意人工核查的候选质量不等于全集召回率。
- `venue_verified`、`ccf_a_verified`：分别记录人工核验通过的数量及所检查数量；不应把“待核验”算作通过。逐论文保存官网或论文集链接、CCF 目录版本、正式发表日期与判断理由。
- `notes`：记录访问时间、查询词、检索页码、模型、网络错误、未核验原因和来源链接。429、网络失败等可作为系统实测失败分别统计，解释原因时不要当成模型能力问题。

建议公式：任务完成率 = 人工判定完成数 ÷ 已执行任务数；工具选择准确率 = 正确选择工具的可评任务数 ÷ 工具选择可评任务数；工具执行成功率 = 成功的实际工具调用次数 ÷ 全部实际调用次数；CCF-A 核验通过比例 = 核验为 CCF-A 的已检查论文数 ÷ 已检查论文数。若分母为 0，请记为不可计算。请同时报告待核验、网络失败、部分结果和样本数，避免只报告通过比例。

人工检查可使用外部浏览器访问论文会议官方页面和 CCF 官方目录；这属于人工核验，不应计作 Agent 自己完成的在线工具调用或自动验证。不要把人工补查后的信息错误归因于系统。
