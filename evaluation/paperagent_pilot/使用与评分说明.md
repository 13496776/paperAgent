# PaperAgent 中文多轮综合测评集

本集包含 320 组、8 类各 40 组：意图与工具选择、指代与查询改写、二次检索、跨论文比较、边界与拒答、会话压缩一致性、混合检索、元数据与范围。六个主题都有覆盖；部分论文及对话模板重复，320 组不等于 320 个完全独立的研究问题。本集由数据库记录和场景模板生成，**不是经过逐条人工审核的标准答案集**。`pilot_dialogues.json` 的 `user_turns` 按序作为用户输入，`scored_turn` 是最后一轮；每段对话必须使用新会话，不能预填理想回答。

## 语料与限制

用户上传的 SQLite 快照 SHA-256：`d63416849e179bebd9450d661f04fb2b9ff5ecb58292c5b7de9198b1d29c70b7`，SQLite 完整性检查通过。`local-user` 下共 104 条记录：89 条 Paperlist 记录加 15 条其他记录；状态分布为 42 条 `ready` 摘要、12 条 `indexing` 摘要、15 条 `indexing` 全文、35 条 `metadata_only`。快照共有 2126 个 chunk。这些状态是上传时的快照，不代表当前运行环境。数据库文件本身含其他会话信息，未纳入本测评集。

检索实现只返回 `ready` 论文内容。每题 `target_papers` 保存快照状态和内容范围，`required_ready_paper_ids` 是该题运行所需的就绪论文；`snapshot_preconditions` 表示快照中尚未满足的条件。**88 组依赖未就绪论文，快照条件下有 232 组可运行**；其中 Agent 自进化方向依赖索引中的全文，不能以缺失检索结果评价模型。完成索引后应检查论文 ID、chunk ID 和内容范围；如果分块发生变化，需要重新校对候选证据。元数据题只要求目标记录存在，不要求全文已经就绪。依赖不同账号、索引或变更后语料的测试结果不能直接与本快照比较。

`evidence_index.json` 是程序挑选的各目标论文首个 chunk，带原始 ID、页码（未知为 `null`）和截取文本；`relevant_chunk_ids` 是**候选证据**，没有逐题验证其能否完整支持题目答案，也没有穷举其他正确片段。引用、研究结论、比较维度、页码及模型裁判都要由人工结合原文或可用摘要复核。不要以候选片段命中率宣称真实 Recall、Precision 或 nDCG。仅凭摘要不能断言全文实验、附录或完整方法；`metadata_only` 不能冒充摘要或全文。

本集限定本地语料，不测在线搜索或联网回退；在线检索应另建可控外部数据集测试。混合检索案例考查同时使用精确关键词及语义表达的意图：只有实际埋点记录了关键词、向量及融合各阶段时，才能判断各路是否执行，现有轨迹无法证明的应标注不可判断。工具名匹配不等于参数、重写质量或检索成功。

## Windows CMD 运行

准备测试专用 SQLite 和对应的 Chroma 索引副本、Redis、模型及密钥，并以 `local-user` 登录；索引文件必须与 SQLite 中记录的模型和向量路径兼容。运行会写入会话和摘要，不要把唯一备份当工作库。下列命令均从项目根目录执行。

第一个 CMD，禁用共享语料和在线工具并启动本地服务：

```cmd
set PAPER_CORPUS_PATH=
set PAPER_EVALUATION_LOCAL_ONLY=1
python run_paperagent.py
```

第二个 CMD，先运行一例检查环境（输入服务输出的访问令牌）：

```cmd
python evaluation/run_pilot.py --dataset evaluation/paperagent_pilot/pilot_dialogues.json --evidence evaluation/paperagent_pilot/evidence_index.json --cases PC-001 --no-judge
```

快照中索引未完成时，运行全部当前可运行案例，并在报告 `skipped_unready` 记录跳过的案例和论文 ID：

```cmd
python evaluation/run_pilot.py --dataset evaluation/paperagent_pilot/pilot_dialogues.json --evidence evaluation/paperagent_pilot/evidence_index.json --skip-unready --no-judge
```

如所有目标论文都已就绪，可去掉 `--skip-unready`。保留该参数也只跳过当前确实未就绪的案例；没有此参数时，运行器会在执行前报出未就绪案例数。`--cases PC-001 PC-041` 可选择具体样本。结果逐例写入 `evaluation_results/`，含对话、工具结果及论文片段。`--no-judge` 不运行模型裁判，需人工评分；去掉后需配置裁判模型和 API Key，问题、回答、工具结果及候选证据会发送给所选模型服务。完整运行需多次模型调用，可能耗时较长并产生费用。结果按案例保存，续跑方法见下。

## 中断后续跑

新版本每次运行创建 `evaluation_results/pilot-.../` 文件夹，`cases/PC-xxx.json` 保存单个案例完整轨迹，`report.json` 保存案例列表和汇总指标。每完成一例便独立落盘，不会把所有轨迹同时保存在内存中。保留整个报告目录；不要只保留 `report.json`。

继续之前的新格式运行：

```cmd
python evaluation/run_pilot.py --skip-unready --no-judge --resume "evaluation_results\pilot-原运行目录名"
```

若中断来自旧版运行器，找到 `evaluation_results` 中最近一次完整保存的 `pilot-*.json` 文件，可直接导入并继续：

```cmd
python evaluation/run_pilot.py --skip-unready --no-judge --resume "evaluation_results\pilot-原报告文件名.json"
```

旧版在写文件时崩溃可能留下不完整的 `.tmp` 文件，**不要**用它作为续跑文件；保留旧 `.json` 原件和 `.tmp` 以便排查。旧报告逐案例读取并复制到新目录，不会覆盖原件；内存占用仍受单个案例大小影响。续跑需使用原数据集、原模型服务和相同的裁判开关，并使用同一账号及语料。旧报告没有数据集内容的哈希，必须人工确认没有换过语料或数据集。续跑跳过所有已有记录，包括失败或状态不明的案例；如要重测某些案例，应单独运行 `--cases`，并将结果与原报告分别保存。崩溃时正在执行但尚未成功落盘的那一例不在已有记录中，续跑会重新执行，检查原日志和后端工作流以确认此前结果及潜在副作用。

若后端再次出现 `WinError 5`、`32` 或 `33`，先检查 `workflow_results` 目录的访问权限，以及同步、杀毒或其他程序是否持续占用文件；程序仅对短暂文件占用做有限次数重试，永久权限错误仍需排查。

## 评分

- 对每一轮记录实际问题、回答、计划、工具名及参数、状态、错误和回执；最后一轮逐项核查 `success_criteria`。最终输出完成不等于答案正确，工具超时和失败单独统计。
- 指代题检查指代对象及改写，不因恰好回答正确就假设内部改写正确；二次检索题显式要求重新检索第二篇，检查目标轮 `retrieve_chunks` 的参数及回执；比较题分别核实两篇支持证据，不能把一篇的结论归给另一篇。
- 边界题统计恰当拒答、澄清或有条件回答的比例，同时在正常问题中报告误拒；缺证据时不能编造数值、页码或绝对保证。
- 压缩题前 7 个用户轮次必须实际完成，目标轮前检查会话产生新摘要、旧消息确实已被压缩，再评估 `memory_checks`，包括后来对回答长度的更新。压缩未成功、未发生或无法确认时标为不可评，不能算成功或失败。自动运行器以新会话的 `summary_id` 和消息数做初步验证，仍须人工核查实际摘要内容和失败 trace。
- 元数据题以该快照记录为准；年份为空就是未知，不应从题目或常识猜测。系统、模型、语料及索引变化后请重验标签。

自动报告的工具选择仅检查必需和禁止工具**名称**；候选片段命中仅是候选片段命中，不代表真正的召回率。模型裁判不是金标，证据不足应标不可判断，并人工抽检。报告中已执行、跳过、失败及未评案例应分开统计并注明分母。本集尚未实跑，不包含模型测评分数。
