# PaperAgent 100 组聚焦测评集

本集替换此前的 320 组试测集，数据集 ID 为 `paperagent-focused-100-v1`。它围绕三项能力设计，每一组均包含至少两轮用户消息；`user_turns` 中每一轮都是完整的问题或针对已有回答的明确要求，不使用单独的“先限定范围”等空转轮次。

| 类别 | 数量 | 测试目标 |
|---|---:|---|
| 混合检索 | 34 | 同时给出缩写、英文技术词及中文问题，在本地语料中重新检索并解释具体证据。 |
| 指代消解 | 33 | 11 组“后者”、11 组话题切换后回指、11 组双实体歧义澄清；每题有参考改写。 |
| 会话压缩一致性 | 33 | 每组第 1–7 轮围绕真实论文开展研究并变更限制，第 8 轮检查对象、范围或后来的格式约束。 |

`pilot_dialogues.json` 的 `success_criteria` 与 `memory_checks` 是预期评分点，`expected_rewrite` 是指代题的参考改写；歧义题不应强行指定唯一论文。`evidence_index.json` 提供对应论文的候选片段与逐字可定位的 `verified_anchor_quote`。我们核对了锚点存在于原始分块，但**相关片段没有穷举、答案和评分条件未经过独立人工双人复核**，不能把这些标签当作完整相关集合或最终金标。混合检索题的答案应有证据，用户问题包含关键词和语义线索；仅凭最终结果或 `retrieve_chunks` 名称，无法确认关键词、向量两路都实际执行，缺少分路埋点时此项记不可判断。

## 语料和索引前提

标注依据用户提供的 SQLite 快照，SHA-256 为 `d63416849e179bebd9450d661f04fb2b9ff5ecb58292c5b7de9198b1d29c70b7`。共选取其中 24 篇有摘要或正文分块的论文，涵盖异常检测、图像编辑、图像超分、Agent 自进化、推理加速和 3D 高斯。快照中 9 组题依赖当时 `indexing` 的论文；当前库中论文状态可能已经发生变化，请以实际运行前检查为准。`snapshot_status` 是**过去快照状态**，不代表最新状态。

当前实现只检索状态为 `ready` 的论文。每题 `required_ready_paper_ids` 包含所有对话轮次依赖的论文；如未就绪，先完成索引，或使用 `--skip-unready` 跳过并报告。完成索引若导致 chunk ID、分块内容或论文元数据改变，应更新并人工复核证据标签，不应将缺索引当作检索模型失败。论文摘要不能支持的实验指标、页码和全文细节应标为证据不足。

使用自己的 `local-user` 账号，固定 SQLite、Chroma、模型和配置；停用共享语料与在线工具。本集测本地检索，不评价在线搜索或 arXiv。保留数据库和 Chroma 备份，测评过程会产生会话记录和模型费用。原 320 组旧报告属于另一个数据集，不能使用 `--resume` 接在这 100 组后面。

## Windows CMD 运行

先在项目根目录启动隔离服务：

```cmd
set PAPER_CORPUS_PATH=
set PAPER_EVALUATION_LOCAL_ONLY=1
python run_paperagent.py
```

第二个 CMD 同样进入项目根目录。要启用模型裁判，请确保已配置 DeepSeek 的 API Key、模型和可用的 API 地址，然后先试运行两个案例（运行时按提示输入后端令牌）：

```cmd
python evaluation/run_pilot.py --cases F100-001 F100-035 --skip-unready
```

确认执行及裁判正常后再运行完整集合：

```cmd
python evaluation/run_pilot.py --skip-unready
```

运行器默认启用模型裁判；报告的 `judge_enabled: true` 表示已创建裁判客户端，不保证每次裁判成功。裁判调用失败、响应无效、证据不足、目标轮未完成或压缩无法确认时，语义分数可能为 `null`；需要查看单例记录和裁判错误，不要算作零分或满分。裁判会向配置的模型服务发送问题、回答、工具回执和参考片段；应对结果进行人工抽检。

如只想采集轨迹而不请求模型裁判，才加 `--no-judge`；此时 `judge_enabled: false`，语义准确率、边界分数及记忆事实一致率没有裁判分母，显示 `0/0` 或 `null` 是预期行为。模型裁判与被测模型共用服务并非独立金标。

每组使用新会话；一组内按顺序复用会话。100 组共 409 个用户轮次，可能触发更多模型和检索调用，耗时及费用都可能较高；先测试小批次并检查错误。每次执行创建报告目录和独立的 `runs/run-.../cases/`，`report.json` 包含累计结果，`run.json` 记录本次计划、跳过及新增案例。报告的 `review.html`、`review.csv` 可筛选案例；包括论文片段、查询和工具结果，请妥善保管。

中断后继续**当前 100 组的同一报告目录**：

```cmd
python evaluation/run_pilot.py --skip-unready --resume "evaluation_results\pilot-实际目录名"
```

续跑参数中的模型服务及是否启用裁判必须与原报告一致。已有记录（包括失败或未知状态）不会自动重跑；查看 `run.json` 的已有和计划 ID。尚未写入报告、但已在后端执行的案例可能被再次运行，先检查实际日志及工作流。另行重测失败案例请用 `--cases` 开启新报告，保留两次结果以供对照。

为任意已有的新格式报告重新建立本地审阅索引，不会重新调用模型：

```cmd
python evaluation/review_report.py "evaluation_results\pilot-实际目录名"
```

生成索引会覆盖同目录下的 `review.html` 和 `review.csv`，手工编辑请先另存。

## 指标和限制

- 分别报告任务执行完成率、工具调用状态及其失败原因；计划 400、服务 500、检索超时和未触发压缩需分开统计，不能都归为模型答错。HTTP 500 不是网络超时的证明，必须查后端堆栈或响应详情。
- 回答正确率只在有可判断的裁判或人工评分时计算；同时公开未评分和无法评分数量。工具名称匹配不是工具参数、查询改写或检索排序正确。
- `labeled_evidence_hit_rate` 使用候选分块，不能当作完整 Recall@k；需以人工或多系统候选池扩展相关标签，才能计算严格检索指标。
- 压缩题只有在前七轮完成、确实发生摘要压缩、且目标轮可判断时，才能计算压缩后记忆正确率。当前程序根据 `summary_id`、消息数和失败 trace 做初步检查，还需要核对实际摘要及压缩前后内容；不能将压缩检查率等同记忆正确率。
- 本集按论文元数据、原文分块和场景模板编写，已做结构、重复和引文位置检查，但语义标签未完成独立人工标注，且尚未完整实跑。不要仅凭本集推断系统在其他语料或场景的普遍性能。
