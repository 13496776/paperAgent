# PaperAgent 中文多轮试测集：使用与评分说明

## 内容和适用范围

- `pilot_dialogues.json`：26 段对话，每段按 `user_turns` 顺序执行，最后一轮为主要计分轮。覆盖论文检索 6、跨论文比较 4、二次检索 3、指代消解 3、边界与拒答 4、压缩后记忆 4、工具选择 2。
- `evidence_index.json`：人工挑选的 21 个代表性证据片段，包含真实论文 ID、chunk ID、序号、页码（缺失为 null）和正文开头，便于复核。
- 该数据库快照校验值为 `db9cbe150657e9603940c4d6de99016297c648d6b59144deae7cdcdf6e70929a`；32 篇论文、4669 个分块，均属 `local-user`。若数据复制或数据库运行期间发生变化，文件级哈希会变化；运行前先在静态原始副本上校验。
- 本集为人工初标的试测集，证据是**代表性正例，未穷举**；不代表完整相关 chunk 集合。论文内容和 PDF 解析文本可能有误，测试前宜结合原文独立复核。大多数论文没有页码，不能把 null 当作第 0 页。
- 仅使用快照中的个人语料，停用 `PAPER_CORPUS_PATH` 共享语料及外部在线检索，或隔离网络并禁止 `search_arxiv` 和 `import_arxiv`。务必使用包含相同论文和分块的个人账号，避免跨用户不同数据导致结果不一致。按项目方式准备对应 Chroma 索引；缺失时系统可能重建索引并产生模型加载成本。
- 保留备份：每个测试条件复制相同初始语料和对应向量索引，避免导入/删除改变结果。SQLite 同时保存摘要，运行会更改数据库；不要直接以原始归档文件作为唯一测试副本。

## 每段对话的执行方法

1. 使用全新的会话 ID，固定模型、配置、论文库和用户；确认一键 JWT 有效，记录软件版本、向量模型、重排模型、chunk 参数、检索参数、阈值、运行时间和数据快照校验值。每段对话不得复用上一段的会话。
2. 按 `user_turns` 逐条向 Web 系统提交用户消息。每轮对系统生成的计划进行确认，等待完成，记录系统真实回答；不要把理想回答预填成助手历史。轮次失败应记录实际状态、错误和未执行的后续轮次，不得当作成功。
3. 最后一轮保存问题、计划、最终回答、工作流和子任务状态、每次工具名称/参数/状态/错误/结果、检索 chunk ID 和排序、耗时。需要更细的 BM25/向量/RRF 阶段结果时，现有输出不一定暴露各路排序，需补充埋点；本数据集本身不是执行器。
4. 逐项依据 `success_criteria` 打分并记录证据。`expected_tools.required_all` 是该目标轮建议必须出现的工具；空列表不等于禁止所有工具。`forbidden` 列表表示该样本约束下不能调用的工具。不要因允许多种合理工具顺序而只做严格序列匹配。
5. 压缩案例必须让前 7 个用户轮次真正运行结束，在目标轮之前核验 SQLite/会话状态存在新 `summary_id`、且旧消息已进入压缩摘要，再执行最后一轮。若压缩失败、未触发、摘要无法读取，标注为 `not_evaluable` 并记录原因，不能按压缩后一致性成功或失败计算；记录 `memory_compression` 失败 trace。确认环境不会跨会话复用历史。
6. 二次检索案例记录前轮和目标轮证据：如果之前已经拿到所需的完整正确证据，应允许复用；题目明确要求再次检索的案例也应另行记录有无再次工具调用，判断是否满足用户指令。

## 指标定义和分母

### 任务完成率

最后一轮的所有 `success_criteria` 经审核成立且无违背约束的行为，计为成功。`任务成功率 = 成功的目标轮 / 纳入评估的目标轮`。另报 `workflow completed` 状态率，不要将 `completed` 直接等同于回答正确。环境未准备、手工中止等不纳入时，要报告排除原因及数量；工具报错、超时及系统运行失败作为系统失败纳入主要结果，另分原因统计。

### 工具执行成功率

`成功执行的实际工具调用次数 / 实际已执行的工具调用次数`；分工具报告失败、超时、429 和调用数。`completed` 只表示执行层返回，结果质量另评。未发生工具调用时分母为 0，结果记为 N/A，而非 100%。同一工具调用内部 HTTP 重试单独统计，不当成多个 Agent 工具调用。

### 工具选择准确率

逐目标轮核对必需工具、禁止工具以及关键参数是否匹配意图（例如计数应调用 `list_corpus_papers`，不得用相似检索估计数量）；允许等价的合理计划经人工记录后计正确。`正确选择工具的可评估目标轮数 / 工具选择可评估目标轮数`。无工具也可能是合理选择。用户约束不允许联网时出现 `search_arxiv` 或 `import_arxiv` 算违规，即使工具本身执行成功。

### 混合检索

对 20 个有 `relevant_chunk_ids` 的目标轮，记录最终返回前 k 个 chunk；系统默认 k=5。对于代表性标签可报告 `标注证据命中率@5 = 检索命中的已标注证据数 / 已标注证据数`，但必须说明标签未穷举、不同方案可能命中其他有效证据，**不得宣称是完整真实 Recall@5 或其无偏估计**。如采用严格 Recall@5、Precision@5、MRR 或 nDCG，必须由人工/多系统候选池扩充并复核相关证据，注明未标注片段处理方式和分母。对于跨论文比较，按 `evidence_groups` 记录是否每篇论文都有被命中的支持证据；若同篇存在其他有效 chunk，应复核后补充。无答案和库存计数等 6 例不计入检索召回分母。区分最终重排/阈值后的结果与各路初召回，不能混用。

### 边界案例恰当拒答率

`正确拒绝/澄清、说明范围且未编造或执行禁止操作的案例数 / 有效边界案例数`。本集 PA-017 至 PA-020 共 4 例；“只回答可证实部分”或发现同轮指令冲突后澄清，可按个案标准算恰当。对答案存在的正常问题拒答另报误拒率。

### 会话压缩后一致性

PA-021 至 PA-024 仅在压缩确实成功、目标轮真实完成后评估。按每例 `memory_checks` 逐条记录正确、错误、无法判断；报告 `正确事实项数 / 可判断事实项数`、全部事实都正确的会话比例、未成功触发压缩的样本数。人工核对是否遵守后来的约束变更、无错误新增与陈旧约束；不能只检查摘要字符串是否包含关键词。

## 关于未支持能力与费用

系统当前不具备完整的图表视觉识别、代码执行和文件导出工具，PA-019 是能力边界测试，不能要求它伪造文件或外部投稿回执。逐轮运行尤其是四个 8 轮对话会触发多次模型调用，可能产生费用与等待；本集尚未执行，不含真实测评成绩。工具失败可能由网络/429、模型配置、索引或程序导致，应保留原始错误并分开报告。
